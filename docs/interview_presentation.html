03 · Separation-of-control principle

Agents receive a scope. They never get to define one.

The application creates an immutable EvidenceCapability for each purpose. Retrieval accepts that server-owned capability—not a user-supplied filter.

Application owns

Requester, account, opportunity, sources, sensitivity, purpose.

Retriever enforces

retrieve(capability, query) produces a bounded bundle.

Governance verifies

Bundle scope before generation; citations and claims afterward.

06 · Prompting strategy

Prompts express the contract; code enforces it.

base_rules.md is layered with one domain prompt per agent and the strategy synthesis contract.

02

03

04

05

06

07 · LiteLLM runtime and security

Provider choice is configuration. The application sees a stable gateway.

Runtime boundary

  • Logical aliases for extraction, risk, synthesis
  • JSON response mode + Pydantic parsing
  • Base URL restricted to HTTP/S
  • LITELLM_API_KEY injected from environment

Persisted telemetry

  • Input hash and model identifiers
  • Latency, token usage, success or safe error
  • No raw prompt or source text in model traces
  • No API credential in persistence

08 · Defense in depth

LiteLLM supplies compute—not authority.

A well-configured gateway cannot compensate for weak application controls. This design makes the deterministic layers decisive.

Permission

Authorization completes before any model request.

Retrieval

Account, opportunity, source, and sensitivity are filtered in SQL.

Governance

Claims, citations, recommendations, and policy outcomes are validated.

09 · Human-in-the-loop design

Risk becomes a structured gate, not a vague “review this.”

RecommendationStructured action, rationale, confidence, evidence
→
Policy engineRoles, reason codes, exact policy rules
→
Human decisionApprove, reject, or request changes

When a gate exists, run status becomes approval_required; the recommendation remains blocked until the gate is satisfied.

10 · Immutable feedback plane

Human decisions become evidence for learning—offline.

The live system never mutates prompts or weights from a reviewer click.

approval_decisions

Who, when, decision, role, and rationale: the operational audit record.

human_feedback

Original recommendation, cited evidence, policy reasons, and the human response.

Offline-only curation reduces poisoning risk and preserves reproducibility.
